# Student profiles are identified by phone number, not `auth.users`

The original `student_profiles` migration (`20260903003047`) modeled students as Supabase-authenticated users: `id uuid primary key references auth.users(id)`. The spec is explicit that students never log in — a student's WhatsApp phone number is their entire identity, auto-creating a minimal record on first contact from an unrecognized number. The Matching Engine is the first feature to actually write `student_profiles` rows, so this had to be resolved before that table could be used: we drop the `auth.users` foreign key, make `id` a plain `gen_random_uuid()`, and add `phone_number text unique` as the natural key. The alternative — giving every admin-entered student a shadow `auth.users` row they can never sign into — just relocates the mismatch into Supabase's auth tables instead of removing it.
